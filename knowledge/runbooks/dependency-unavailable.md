# An unavailable dependency

## Symptoms
Callers report connection failures, DNS failures or timeouts to the same downstream component. The caller may be healthy and wrap the downstream error. A failing client span may have no matching server span.

## What to check first
Use `get_traces(service=<caller>, errors_only=True, lookback_s=120)` to identify the destination and missing server child, then `get_container_health(names=[<dependency>])`. Corroborate with `get_logs(service=<caller>, severity_min="INFO", lookback_s=120)` and `get_metrics(promql="error_rate_by_service", lookback_s=300)`. Broaden the trace window to 600 seconds if stalled requests started before the short window.

## How to confirm
Separate an unavailable backing component from a caller misrouting to an unrelated address. Name the backing component when its unavailability is supported. Change the category to container_down if a stopped container is proved. A timeout alone does not identify the dependency's process state or a network fault.

## Allowed remediation
Where evidence supports restoring the backing component, propose Action API `restart_service` with that component as `service`, subject to the allowlist and human approval after a dry run. Confirm persistence risk for a stateful service. Escalate unsupported targets and ambiguous paths.

## Rollback
There is no process-state rollback for restart. If callers fail to recover, escalate and retain both dependency and caller observations.

## Verification criteria
Observe fresh successful downstream calls and recovery of the caller's original signals. Verify the underlying dependency, not merely the alerting frontend's process state.

## Prevention
Monitor critical dependency edges with request outcomes, timeouts and retry saturation. Keep the service catalogue current when the deployment changes.

## Known pitfalls
Compose depends_on records startup ordering, not every runtime RPC edge. A shared error text can be generated by an application failure as well as a real dependency outage. Follow the cache runbook for cart storage failures.
